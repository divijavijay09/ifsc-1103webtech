Thoughts on Progressive Enhancement

Progressive enhancement is a way of building websites that prioritizes content over anything else. Before this way of web development, developers would only think about how to make sure their webpage worked on the newest browsers, and not care about the old browsers. With progressive enhancement, developers focus on ensuring that every user can access the webpage's information, regardless of their resources or connection. In the article, Aaron Gustafson described progressive enhancement with a peanut M&M analogy that did a great job of explaining the layers. At the core, there is the peanut, which is the HTML foundation that houses all of the content. For people who cannot see the design of the webpage, the content still satisfies their needs. Next, there is the chocolate coating, which is the CSS layer. This is for people who have the resources to load the CSS on the webpage. This only adds to their experience when visiting a site. It is also helpful for times when IT security disables JavaScript. Finally, there is the hard candy shell, which is the JavaScript layer. This just adds interactivity.

Progressive enhancement is important because it allows users to access the main content of a site even if the outer layers are not available or their device cannot handle it. It makes websites accessible to everyone, no matter their device or software. Another thing to note is that users who rely on screen readers are mainly focused on the content of a site, so the CSS or JavaScript would affect their experience. So instead of developers only focusing on building sites for the newest technologies, they focus on user accessibility, because after all, the site they are making is for others. Progressive enhancement helps make sure that webpages do not break easily and the content/foundational HTML will always be available.

Final Project Revision and Reflection

This semester has been a lot of fun. I really enjoyed learning how to build my own website from scratch. Now, whenever I look at any website, I can’t help but notice the HTML structure and guess which CSS attributes they used. I think I did a good job with the HTML part because it was the easiest for me to understand. I also did pretty well with the CSS design. I had a little bit of trouble at first with targeting specific sections, but the CSS Diner assignment actually helped me understand how to target specific elements quite well.

If I had to start this project over, I don't think I would change my process. I like the flow of starting with the content in HTML and then adding the CSS style element by element. However, if I were starting the whole course again, I would pay more attention to the harder CSS rules, like the nth-child selectors. I also want to learn more JavaScript so that I can have the whole peanut M&M experience with all 3 layers of web development.

I showed my first draft to a peer, and they gave me some good advice. They told me that I needed to add more pages (obviously, since the draft was only one page) and a contact form to make it a finished project. They also suggested some small design fixes, like making the header border solid instead of dashed and making one of the headers a darker color to make it easier to read. There were also a few spelling and small semantic errors that they helped point out. Additionally, they helped me fix my image issue of making it fit between lines in a section. I accepted all of their feedback and made those changes because their advice only enhanced my site and made it look better. I also finished adding the extra pages, the form for my final version, and fixed the small errors.
